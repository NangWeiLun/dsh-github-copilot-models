# AGENTS.md

A GitHub Copilot plugin for DeepSeek Harness (DSH). Two parts: **Login** (browser device code, or a PAT) and **Models** (the model list fetched live from the Copilot API, with an on/off toggle per model). The design is in `docs/design/`.

## Rules

- **No HTTP or API request to GitHub or Copilot without the developer's permission**, one request at a time. This covers `github.com`, `api.github.com` and the Copilot API hosts (`*.githubcopilot.com`), including opening a page in a browser. Web search is fine.
- **Business PAT:** do not send the fine-grained PAT of a Copilot Business account to the Individual endpoint `https://api.individual.githubcopilot.com`. This has blocked the account's access to GitHub Copilot for about an hour. Send requests only to the Copilot API host that the host lookup reports for the account (login.md A3).
- **Reference repos:** `repos/` holds local clones of similar plugins. It is git-ignored; clone them as described in [docs/study/ref-similar-plugins.md](docs/study/ref-similar-plugins.md), which also says what each repo is and where to look in it. Use them whenever it helps, read only. `dsh-plugin-copilot` has no LICENSE file; its `package.json` declares MIT. Reuse no code from it.
- **Profiles:** the plugin may be developed in the developer's own profile, with this checkout installed as a local link, or in a separate profile such as `web-dev`. A profile's `~/.dsh/profiles/<profile>/package.json` shows which: `"dsh-github-copilot-models": "link:<this folder>"` for a local install, a version for an npm one.
- **Breaking change with a local install:** when a change in this checkout could break the plugin in a profile that installs it as a local link (it would stop loading or working there, or change its stored settings, its route id or the shared credential record), and the developer has not said to keep working in local mode, ask before going on: should that profile install the plugin from npm instead (`dsh plugin --profile <profile> remove dsh-github-copilot-models`, then `dsh plugin --profile <profile> add dsh-github-copilot-models`, then restart that profile's DSH), with development moving to another profile such as `web-dev` (`dsh plugin --profile web-dev add <this folder>`)? Until the plugin is published on npm, offer to remove the local link from that profile instead.
- **Early stage:** refactor or rewrite freely. No backward compatibility, shims or migrations.
- **Secrets:** a PAT for live tests goes only in `.env` (git-ignored). Never print, log or commit it. Saved API responses go in `schema/` (git-ignored) and hold account data: never print or commit them.
- **Real response schema:** when checking a real API response schema, save the full detail to `schema/<name>.json`.

## Develop and test

Setup, profile, run, test and troubleshooting steps for people are in [DEVELOPMENT.md](DEVELOPMENT.md). The short version:

- **Official guide:** [Develop a plugin](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/) (first plugin, config, [package and install](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/publish), [LLM adapters](https://deepseek-harness.github.io/deepseek-harness/en/develop/practice/llm-adapter)). The installed DSH also ships the `cordis-plugin-development` skill in `dsh-agent-preset/skills/`.
- **Build and check:** `npm run check` (type-check, unit tests, build). `npm run test:contract` checks the installed DSH and pi-ai offline; it never sends a request.
- **The `web-dev` profile:** create it once with the commands in DEVELOPMENT.md section 3: a fresh copy of DSH's `web` template, with this checkout linked. Credentials are per DSH home, so web-dev shares `~/.dsh/.credentials.yaml` with every other profile in that home.
- **Run web-dev** on port 3081 from `.tmp/web-dev-cwd`, logging to `.tmp/web-dev.log`: `npx -- @deepseek-ai/dsh --profile web-dev --port 3081 --no-open`. Unset `DSH_PROFILE`, `DSH_PROFILE_DIR`, `DSH_SESSION_ID`, `DSH_WEB_URL` and `DSH_SHELL` first when launching from inside a DSH session. Keep web-dev stopped while the code is not ready, and stop it before `npm run build`: a rebuild followed by any Card setting change reloads the plugin, which sends the start-up requests (DEVELOPMENT.md section 4).
- **Separate checkout:** work in progress can live in another checkout of this repository, such as a git worktree; how it is made depends on the developer's tools. Its build reaches no profile, so a profile with the local link (for example the developer's everyday profile) keeps running the main checkout's build until the work is merged and built there. For a browser check, point web-dev at that checkout (`dsh plugin --profile web-dev add <checkout>`) and back at the main checkout afterwards. It has no `.env`, and the Copilot login stays shared by every profile (DEVELOPMENT.md section 3).
- **Live Host calls** without a browser: `node scripts/dev-host.mjs state|notices|save-pat|refresh|sign-out|leak-check`. It reads the launch URL from the log and the PAT from `.env`, and prints neither. `save-pat` and `refresh` each send two requests: the host lookup and `GET /models`.
- **Requests while a record exists:** every web-dev start or plugin reload sends the host lookup and `GET /models` (login.md A3, models.md A3). Sign out before stopping if no request is wanted at the next start.
- **Screenshots:** take viewport-sized screenshots only, never full-page ones, and prefer reading the page as text. Copilot refuses a request with many images once one is over 3000 px on a side, and the session cannot continue.
